# Mentora — платформа онлайн-курсів

Робочий demo-проєкт для портфоліо: платформа онлайн-курсів з каталогом, сторінкою курсу та кабінетом студента. 3 екрани, реальні API-роути (запис на курс і прогрес зберігаються на сервері), справжні фото з Unsplash, кастомна анімаційна система на Framer Motion.

## Стек

- **Next.js 16** (App Router, Turbopack) + **TypeScript**
- **Tailwind CSS 4** (CSS-first `@theme` — токени в `src/app/globals.css`, без `tailwind.config.ts`)
- **Framer Motion** — 3D-tilt картки курсів, розкриття акордеону програми курсу, анімовані SVG-кільця прогресу, кероване layout-перемикання фільтра категорій
- Реальні фото — Unsplash (`online learning`, `coding workshop`, `design course`, `data analytics`, `digital marketing`, headshot-портрети викладачів), усі посилання перевірені `curl -I` перед вбудовуванням
- Реальний бекенд — Next.js Route Handlers з in-memory сховищем (без БД, як і у проєкті 2)

## Екрани

| Маршрут | Що там |
|---|---|
| `/` | Каталог курсів: сітка з 9 карток, фільтр за категорією (`layoutId`-анімація пігулки), на ховері картки — 3D tilt за курсором, підйом тіні й опис, що висувається знизу |
| `/courses/[slug]` | Сторінка курсу: постер + кастомна play-кнопка з ripple-ефектом (без реального відео — свідомий мок), акордеон програми з плавним розгортанням висоти, картка викладача, кнопка запису на курс |
| `/dashboard` | Кабінет студента: картки "моїх курсів" з анімованими SVG-кільцями прогресу (`stroke-dashoffset`), карусель "продовжити перегляд", бейджі досягнень із shine-анімацією для отриманих і grayscale/lock для не отриманих |

## Чому це "робочий" проєкт, а не просто фронтенд

На відміну від оригінального технічного завдання (яке просило зробити цей екран заглушкою без бекенду — рішення свідомо змінене на повний стек), тут є реальний цикл запит/відповідь:

- `POST /api/enroll` — записує студента на курс у серверному сховищі. Повторний запис на той самий курс повертає той самий enrollment ідемпотентно; запис на неіснуючий курс повертає справжню 404.
- `POST /api/progress` — перемикає позначку "пройдено" для конкретного уроку, перераховує відсоток проходження курсу на сервері. Спроба відмітити урок без запису на курс повертає 403.
- `GET /api/courses` — каталог із фільтром за категорією (`?category=`); невідома категорія повертає 400.
- `GET /api/dashboard` — обчислює на сервері прогрес, "продовжити перегляд" і досягнення студента з реального стану сховища.

Спробуйте: зайдіть на курс, натисніть "Записатися на курс", відмітьте урок у програмі — і відкрийте `/dashboard`: прогрес і бейджі відображають щойно збережені на сервері дані, а не локальний стан компонента.

**Немає БД (це demo)** — стан живе в `globalThis` у пам'яті Node-процесу (`src/lib/store.ts`) і скидається при рестарті сервера. Для консистентності при hot-reload у розробці сховище прив'язане до `globalThis`, а не до модуля — інакше Next.js dev-сервер перестворював би його на кожен запис у файл.

Демо-студентці "Софія Дем'яненко" при старті сервера засіяно 4 записи на курси з різним прогресом (у т.ч. один курс на 100%), щоб кабінет одразу виглядав живим для скріншотів — усі подальші дії (запис на новий курс, позначення уроків) реально мутують це сховище поверх засіяного стану.

## Ключові компоненти

```
src/
├── data/courses.ts                    # 9 курсів, повна програма (4 модулі × 3 уроки) кожного
├── lib/
│   ├── types.ts                       # Course, Module, Lesson, Instructor
│   ├── courses.ts                     # читання каталогу: getAllCourses, getCourseBySlug, toSummary
│   └── store.ts                       # in-memory enrollments/progress, seed, achievements
├── app/api/
│   ├── courses/route.ts               # GET, фільтр за категорією
│   ├── enroll/route.ts                # POST, реальна валідація + ідемпотентність
│   ├── progress/route.ts              # POST, toggle уроку + перерахунок прогресу
│   └── dashboard/route.ts             # GET, обчислений стан кабінету студента
├── components/
│   ├── catalog/CourseCard.tsx         # pointer-based 3D tilt (useSpring + useMotionTemplate), hover-reveal опису
│   ├── catalog/CategoryFilter.tsx     # анімована пігулка через layoutId
│   ├── course/CourseDetail.tsx        # клієнтський оркестратор: enroll + progress стан, реальні fetch-виклики
│   ├── course/Syllabus.tsx            # акордеон із AnimatePresence height:auto
│   ├── course/VideoPlayerMock.tsx     # постер + play-кнопка з ripple-пульсацією
│   ├── dashboard/ProgressRing.tsx     # SVG-кільце, strokeDashoffset анімується від 0 при монтуванні
│   ├── dashboard/ContinueCarousel.tsx # горизонтальна scroll-snap карусель
│   └── dashboard/AchievementBadges.tsx # shine-sweep для отриманих бейджів (globals.css: .badge-shine-sweep)
```

## Запуск локально

### Одна команда з кореня репозиторію
```bash
npm run prot:mentora
```
Підніме сайт на `http://localhost:3211`.

Або разом з іншими demo-проєктами:
```bash
npm run prot
```

### Вручну
```bash
cd portfolio-demos/03-mentora-courses
npm install
npm run dev
```

### Продакшн-білд
```bash
npm run build
npm run start
```

## Технічні нотатки

- **`next.config.ts`**: `images.remotePatterns` дозволяє `images.unsplash.com` без заданого `search` (як і в проєкті 2) — усі посилання на Unsplash містять query-параметри, тож порожній `search: ""` повертав би 500.
- **`turbopack.root`** явно вказаний на директорію проєкту, щоб Next не плутав корінь workspace із коренем монорепо через кілька `package-lock.json` у дереві.
- **Сховище через `globalThis`, не модульний singleton**: Next.js dev-сервер перестворює модулі при кожному hot-reload; без прив'язки до `globalThis` записи студента скидалися б після кожного збереження файлу під час розробки.
- **Palette**: тепла паперова основа (`--color-paper`) + глибокий мох (`--color-moss`) + теплий бронзовий акцент (`--color-gold`) замість типової для edtech синьо-фіолетової гами — свідомий вибір, щоб не виглядати як типовий AI-шаблон.
- **Шрифти**: `Instrument Serif` (курсив, дисплейні заголовки) + `Manrope` (текст/інтерфейс) — інша пара, ніж у проєкті 2 (Fraunces/Work Sans), щоб кожен demo мав власний почерк.
